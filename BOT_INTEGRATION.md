# Підключення вашого Telegram-бота

Контракт версії 3: ціна магазину з +20%, валюта UAH або USD, Telegram Mini App, замовлення в Upstash Redis. Код самого бота не був у початковому архіві, тому описаний обробник треба додати до нього.

## Передача

Після перевірки кошика frontend отримує:

```json
{
  "id": "opaque-40-character-order-id",
  "status": "awaiting_bot_checkout",
  "currency": "UAH",
  "totalMinor": 48000,
  "totals": {"UAH": 48000, "USD": 1200},
  "telegramUserId": 4242,
  "createdAt": 0,
  "expiresAt": 0,
  "botUrl": "https://t.me/YourBot?start=order_opaque-id",
  "items": []
}
```

Числа наведені лише як приклад на тестових курсах. `priceMinor` і `totalMinor` — копійки/центи, час — Unix seconds. `telegramUserId` містить перевірений ID тільки якщо налаштовано `TELEGRAM_BOT_TOKEN`; інакше `null`. `initDataUnsafe` не використовується як доказ особи.

Коли користувач натискає «Продовжити в боті», `openTelegramLink` відкриває посилання. Бот отримує `/start order_<id>`.

## Серверне отримання замовлення

```http
GET https://your-site.vercel.app/api/bot/orders/<id>
Authorization: Bearer <BOT_API_SECRET>
```

Endpoint повертає замовлення з `items`, де додатково присутні серверні поля:

```json
{
  "id": "123456",
  "title": "Steam account",
  "currency": "UAH",
  "priceMinor": 48000,
  "prices": {"UAH": 48000, "USD": 1200},
  "supplier": {"currency": "RUB", "priceMinor": 100000},
  "pricing": {
    "markupPercent": "20",
    "usdRates": {"USD": "1", "UAH": "40", "RUB": "100"},
    "updatedAt": 0
  }
}
```

`priceMinor` — продажна ціна, `supplier` — закупівельна. **Не застосовуйте націнку повторно.** Сума до оплати — `totalMinor` у `currency`. Інша валюта показана як еквівалент; вона не змінює валюту створеного замовлення. Поля `supplier` та `pricing` не віддаються браузеру.

`401` — неправильний серверний секрет. `404` — запис не знайдено. `410` — перевірці більше 15 хвилин. `503` — недоступне сховище.

## Логіка, яку слід додати до бота

1. Перевірити формат аргументу `/start`: `order_` + 40 шістнадцяткових символів.
2. Отримати запис через HTTPS endpoint із `BOT_API_SECRET`.
3. Якщо `telegramUserId` заданий, порівняти його з Telegram ID відправника. Якщо `null`, атомарно прив'язати замовлення до першого користувача, який його підтвердив, у базі бота. Посилання можна переслати.
4. Зберігати платіжні стани і вже видані товари у базі бота. Повторне відкриття одного ID не має створювати другий платіж або другу закупівлю.
5. Повторно перевірити наявність і закупівельну ціну до оплати. Якщо потрібна інша сума, створити нову пропозицію з явним підтвердженням користувача, а не змінювати стару суму непомітно.
6. Створити платіж у вибраній валюті за `totalMinor` через вашу платіжну інтеграцію. Довіряти тільки підтвердженню від провайдера, перевіреному на сервері.
7. Після підтвердження оплати купити потрібні item ID вашою LZT-інтеграцією і видати дані цьому покупцеві у приватному чаті. Timeout закупівлі не означає невдачу: перед повтором перевірити її фактичний статус.
8. Обробляти зникнення товару, частковий успіх і повернення коштів. Саме збереження кошика товар не резервує.

## Налаштування

У Vercel та в боті задайте однаковий випадковий `BOT_API_SECRET`. У Vercel також задайте `TELEGRAM_BOT_USERNAME`; після реалізації обробника рекомендовано задати `TELEGRAM_BOT_TOKEN`, щоб сайт перевіряв HMAC `initData` і вік сесії до 1 години.

Не вмикайте username випадкового бота: без реалізованого `/start order_` він не знатиме, що робити із замовленням. Платіжна логіка та видача не реалізовані в цьому frontend/API-проєкті.
